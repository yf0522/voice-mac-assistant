语音流 & Live API 架构

实时双向通道

Electron 双进程：主进程（Node）负责窗口/托盘、IPC、本地动作执行；渲染进程（Chromium）负责 UI、音频采集与播放。唤醒词由 Porcupine 在本地离线监听，命中后才建立 Gemini Live 会话——平时不上传任何音频，省额且护隐私。

🎙️采集

渲染进程用 Web Audio AudioWorklet 取 16-bit PCM 16kHz 单声道，分帧推流。

🌐传输

WebSocket 直连 Gemini Live（BidiGenerateContent），边说边传、可中途打断。

🔉播放

收 24kHz PCM 入 Web Audio 播放队列，支持 barge-in 打断回放。

会话状态机（待机 ↔ 激活 · 连续对话 · 静默回收）：唤醒后进入连续对话，期间无需重复说「贾维斯」；用 VAD 检测语音，每次你说话或 AI 回复都重置 5 分钟静默计时；静默满 5 分钟则关闭 Live 会话回到待机（省额 + 守隐私）。也支持说"退下/再见"主动收尾。

意图返回结构设计（Function Declarations）

结构化而非关键词

用 Gemini Live 原生的 tool / function calling：在建会话时下发 functionDeclarations，模型理解语义后返回明确的 toolCall（动作名 + 参数 JSON Schema 约束），本地执行后用 toolResponse 回传。比关键词匹配更稳、更可控。

// 建立会话时下发的工具声明（节选）
const tools = [{
  functionDeclarations: [
    { name: "open_app",    description: "打开 macOS 应用",
      parameters:{ type:"object", properties:{ app_name:{type:"string"} }, required:["app_name"] }},
    { name: "set_volume",  description: "设置/调整系统音量",
      parameters:{ type:"object", properties:{ level:{type:"number"}, delta:{type:"number"} }}},
    { name: "list_directory", description: "列出目录内容（沙箱限用户目录）",
      parameters:{ type:"object", properties:{ path:{type:"string"} }, required:["path"] }},
    { name: "launch_dev_tool", description: "在 iTerm2 打开项目并调起 Claude Code / VS Code / Gemini CLI",
      parameters:{ type:"object", properties:{
        tool:{ type:"string", enum:["claude","code","gemini"] },
        project_path:{ type:"string" } }, required:["tool"] }},
    { name: "run_shell",   description: "受限 shell（白名单+确认）",
      parameters:{ type:"object", properties:{ command:{type:"string"} }, required:["command"] }}
  ]
}];

模型返回示例：

// “打开 Safari”
{ "toolCall": {
  "name": "open_app",
  "args": { "app_name": "Safari" }
}}
// “看下下载文件夹”
{ "toolCall": {
  "name": "list_directory",
  "args": { "path": "~/Downloads" }
}}

三级安全网关（你选的「白名单 + 危险确认」）：每个 toolCall 先过网关分级，再决定直接执行 / 弹窗+语音确认 / 直接拒绝。

绿色 · 安全

只读或低风险，直接执行无打扰。

open_app · query · list_dir · volume · lock

黄色 · 需确认

改动文件 / 退出 App / 白名单内 shell，弹窗 + 语音二次确认。

move · rename · quit_app · run_shell(白名单)

红色 · 拒绝

白名单外破坏性命令，直接拒绝并语音告知，永不执行。

rm -rf · sudo · dd · mkfs · 路径越界
⚠️ 提示注入防线：命令前缀白名单 + 路径沙箱（限定用户目录）+ 参数校验三道叠加，即使模型被诱导生成危险命令也被网关拦在执行器之外。

⌨️开发工具调起（iTerm2）

launch_dev_tool 用 AppleScript 驱动 iTerm2：新建窗口/标签 → cd 到项目目录 → 执行 claude / code . / gemini。项目路径过沙箱校验，tool 限定枚举三选一，不接受任意命令注入。例：

// “在 glyph 项目里开 Claude Code”
{ "toolCall":{ name:"launch_dev_tool",
  args:{ tool:"claude", project_path:"~/workSpace/glyph" }}}
// → osascript 让 iTerm2: cd ~/workSpace/glyph && claude
// → 语音：“已在 iTerm2 里为 glyph 启动 Claude Code”

反馈机制

结果回灌生成语音

执行器把结果整理成结构化 toolResponse（成功/失败 + 数据/错误摘要）回传 Gemini，模型据此生成自然语音；UI 同步显示动作日志。命令失败时把 stderr 摘要回传，AI 会解释原因并给建议，而不是干巴巴报错。

// 成功
{ "toolResponse":{
  name:"list_directory",
  response:{ ok:true,
    items:["报告.pdf","截图.png"],
    count:2 }}}
// → 语音：“下载夹里有 2 个文件…”
// 失败
{ "toolResponse":{
  name:"move_file",
  response:{ ok:false,
    error:"目标已存在" }}}
// → 语音：“那边已有同名文件，要覆盖吗？”
